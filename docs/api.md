# API REST — EduvIA

> **Resumen.** 34 operaciones bajo el prefijo `/api/v1`, documentadas en detalle en [`docs/backend/openapi.yaml`](backend/openapi.yaml) y derivadas del contrato [`docs/backend/api-contract.md`](backend/api-contract.md). La compatibilidad verificada con la app KMP está en [`docs/backend/compat-report.md`](backend/compat-report.md); la arquitectura del servidor, en [`docs/backend.md`](backend.md).

## Convenciones globales

| Concepto | Convención |
|---|---|
| Base path | `/api/v1`; las rutas de la tabla se muestran ya con el prefijo completo. |
| Naming JSON | `camelCase`, sin `@SerialName` ni `namingStrategy`. |
| IDs | `Long` (`bigint generated by default as identity`), no UUID; claves compuestas para entregas y respuestas. |
| Fechas | `YYYY-MM-DD` para `date`, `dueDate`, `publishedDate` y `dateText`; timestamps ISO-8601 UTC para `createdAt`/`updatedAt`. |
| Horas | Texto validado por la app (por ejemplo `8:00 am`); el backend compara en minúsculas para detectar duplicados. |
| Enums | Literales exactos en mayúsculas: `PARENT/TEACHER`, `PENDING/DELIVERED/EXPIRED`, `ATTENDING/DECLINED`, `TASK/MEETING/EXAM`, etc. |
| Paginación | `PageResponse<T> { items, page, size, totalElements, totalPages }`; `page` empieza en 0, convención `size=20`, tope máximo 100 ([Q2](backend/OPEN-QUESTIONS.md)). |
| Errores | RFC 9457 `ProblemDetail` con `type`, `title`, `status`, `detail`, `instance` y `properties.errors`. `Content-Type: application/problem+json`. |
| Autenticación | `Authorization: Bearer <accessToken>` en todos los recursos salvo `/api/v1/auth/**`, health de Actuator, Swagger/OpenAPI y `/error`. Un 401 lleva `WWW-Authenticate: Bearer`. |
| Cuerpos vacíos | `204` sin contenido para logout y borrados; `postNoContent`/`deleteNoContent` de la app los aceptan. |

## Operaciones (34)

### Autenticación y cuenta — A1–A9

| Id | Método | Ruta | Descripción |
|---|---|---|---|
| A1 | `POST` | `/api/v1/auth/register` | Registro de cuenta (y grupos o hijos) en una sola transacción. |
| A2 | `POST` | `/api/v1/auth/login` | Inicio de sesión; devuelve usuario y tokens. |
| A3 | `POST` | `/api/v1/auth/refresh` | Renueva access/refresh con rotación del refresh. |
| A4 | `POST` | `/api/v1/auth/logout` | Revoca el refresh token enviado. |
| A5 | `GET` | `/api/v1/auth/exists/email?email=` | Comprueba si el correo ya está registrado. |
| A6 | `GET` | `/api/v1/auth/exists/phone?phone=` | Comprueba si el teléfono ya está registrado. |
| A7 | `POST` | `/api/v1/auth/reset-code` | Genera código de recuperación; en `dev` se devuelve en la respuesta. |
| A8 | `POST` | `/api/v1/auth/reset-password` | Restablece la contraseña con el código vigente. |
| A9 | `GET` | `/api/v1/me` | Usuario autenticado. |

### Grupos y alumnos — G1–G7

| Id | Método | Ruta | Descripción |
|---|---|---|---|
| G1 | `GET` | `/api/v1/groups?teacherId=` | Grupos del docente, paginados. |
| G2 | `GET` | `/api/v1/groups/{id}` | Detalle de un grupo. |
| G3 | `GET` | `/api/v1/groups/by-code?code=` | Grupo por código de clase (sin distinción de mayúsculas). |
| G4 | `POST` | `/api/v1/groups` | Crea un grupo con código `XX-YYYY` único. |
| G5 | `GET` | `/api/v1/groups/{id}/students` | Alumnos del grupo, paginados. |
| G6 | `GET` | `/api/v1/students?parentId=` | Hijos vinculados a un padre/tutor. |
| G7 | `POST` | `/api/v1/students:link` | Vincula un alumno al padre mediante el código de clase. |

### Tareas — T1–T6

| Id | Método | Ruta | Descripción |
|---|---|---|---|
| T1 | `GET` | `/api/v1/tasks?groupId=&page=&size=` | Tareas del grupo ordenadas por fecha; `groupId` es obligatorio. |
| T2 | `GET` | `/api/v1/tasks/{id}` | Detalle de tarea con `status` derivado y entregas. |
| T3 | `POST` | `/api/v1/tasks` | Crea tarea y su evento `TASK` con el mismo id. |
| T4 | `PUT` | `/api/v1/tasks/{id}` | Edita tarea existente. |
| T5 | `DELETE` | `/api/v1/tasks/{id}` | Borra tarea y su evento de calendario. |
| T6 | `POST` | `/api/v1/tasks/{id}/deliveries` | Marca una entrega de forma idempotente. |

### Juntas — M1–M9

| Id | Método | Ruta | Descripción |
|---|---|---|---|
| M1 | `GET` | `/api/v1/meetings?page=&size=` | Juntas paginadas, ordenadas por fecha; calcula `isNext`/`relativeLabel`. |
| M2 | `GET` | `/api/v1/meetings/{id}` | Detalle de una junta. |
| M3 | `POST` | `/api/v1/meetings` | Crea junta y evento `MEETING` con id `1000 + id`. |
| M4 | `DELETE` | `/api/v1/meetings/{id}` | Borra junta, evento y respuestas. |
| M5 | `GET` | `/api/v1/meetings/{id}/attendance` | Asistencia derivada de las respuestas, paginada. |
| M6 | `PUT` | `/api/v1/meetings/{id}/responses/{studentId}` | Registra la respuesta de una familia. |
| M7 | `GET` | `/api/v1/meetings/responses?studentId=` | Mapa `meetingId` → respuesta de un alumno. |
| M8 | `POST` | `/api/v1/meetings/{id}/reminders` | Devuelve cuántas familias siguen `PENDING`. |
| M9 | `PUT` | `/api/v1/meetings/{id}` | Edita junta y evento `1000+id` sin detectarse a sí misma como duplicado. |

### Calendario — C1–C3

| Id | Método | Ruta | Descripción |
|---|---|---|---|
| C1 | `GET` | `/api/v1/calendar/events?role=&page=&size=` | Eventos por rol; `attendance` solo para `TEACHER`. |
| C2 | `POST` | `/api/v1/calendar/events` | Crea un evento (la app lo usa para `EXAM`). |
| C3 | `DELETE` | `/api/v1/calendar/events/{id}` | Borra un evento del calendario. |

> Reglas de negocio completas (registro atómico, códigos de grupo, sincronización tarea/junta con calendario, duplicados, idempotencia y códigos de reset): ver [`docs/backend/api-contract.md`](backend/api-contract.md).

## Cómo explorar la API

Con el backend en marcha en el puerto local por defecto (`8080`):

- Swagger UI: <http://localhost:8080/swagger-ui.html>
- Documento OpenAPI JSON: <http://localhost:8080/v3/api-docs>
- Healthcheck: `GET /actuator/health` (público)

Si el stack se levanta con un `API_PORT` distinto, sustituye `8080` por ese puerto. La comparación entre el documento generado en runtime y el diseño dio `design=34`, `runtime=34`, `missing=[]`, `extra=[]`, 26 paths y 36 schemas ([`compat-report.md`](backend/compat-report.md)).
